# Business Metric Assumptions

## 1. Purpose

This document explains the business metric used to estimate the analyst workload generated by LinkShield-AI when screening URLs for phishing threats.

The purpose is to translate model predictions into an understandable operational metric: the estimated time required by security analysts to review flagged URLs.

## 2. Selected Business Metric

**Estimated Analyst Review Time (Hours)**

This metric estimates how many analyst hours may be required to review URLs flagged by the model as phishing.

It helps demonstrate the potential operational workload associated with deploying the system in a bank's URL-screening workflow.

## 3. Calculation Formula

The estimated review time is calculated as:

`Review Hours = ((TP + FP) * M) / 60`

Where:

- **TP (True Positives):** Phishing URLs correctly identified by the model.
- **FP (False Positives):** Legitimate URLs incorrectly flagged as phishing.
- **M:** Assumed average review time per flagged URL, measured in minutes.
- **60:** Converts minutes into hours.

The calculation includes both true-positive and false-positive alerts because both may require analyst attention.

## 4. Assumptions

The following assumptions are used:

1. Each URL flagged as phishing is considered an alert requiring analyst review.
2. The average review time is assumed to be 1, 3, or 5 minutes per alert.
3. The calculation uses the baseline model's test-set results.
4. The test-set phishing prevalence is used as the reference distribution.
5. These review-time values are illustrative assumptions, not measurements collected from real bank analysts.
6. The calculation does not represent actual financial savings or confirmed fraud prevention.

## 5. Baseline Results

The baseline model produced the following confusion matrix:

| Metric | Value |
|---|---:|
| True Positives (TP) | 20,008 |
| False Positives (FP) | 1 |
| False Negatives (FN) | 94 |
| True Negatives (TN) | 26,969 |

The test set contains 47,072 URLs.

## 6. Estimated Workload per 10,000 URLs

Using the test-set class distribution, the estimated number of alerts per 10,000 screened URLs is approximately 4,250.7.

| Assumed Review Time | Estimated Analyst Hours |
|---|---:|
| 1 minute per alert | 70.8 hours |
| 3 minutes per alert | 212.5 hours |
| 5 minutes per alert | 354.2 hours |

These values are estimates based on the stated assumptions and are not measured operational results.

## 7. Limitations

- The dataset is not a sample of actual bank traffic.
- The assumed analyst review times have not been validated through interviews or operational measurements.
- Actual workload depends on the number of URLs screened, alert-handling procedures, and analyst workflows.
- The baseline model has not been validated for production banking environments.
- The metric estimates review workload only; it does not calculate financial savings or prevented losses.

## 8. Conclusion

Estimated Analyst Review Time provides a simple way to translate model predictions into a potential operational workload.

It offers an initial business-oriented measure for Phase 1. Real deployment decisions would require validation using representative banking traffic and measured analyst review times.
